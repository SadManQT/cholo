Do this first: make the site public

Right now cholo-cholo7.vercel.app redirects everyone who isn't logged into your Vercel account to Vercel's login page. It isn't a code problem; it's Vercel's Deployment Protection, which by default covers every URL except the project's production domain.

  1. Vercel → the cholo project → Settings → Deployment Protection.
  2. Set Vercel Authentication to Disabled, then Save. (Or keep it on and add a production domain under Domains; production domains are exempt.)
  3. Open the site in a private window to confirm it loads, then make sure Render's CLIENT_ORIGIN lists that exact address. It now accepts several, comma-separated, e.g. https://cholo-cholo7.vercel.app,https://cholo.app.

Launch essentials

What a real public launch needs beyond what works today.

Real SMS for sign-up and password codes

Codes are only written to Render's logs today, so nobody but you can finish signing up or resetting a password.

Before real usersNeeds a providerS

How to add

  1. Open an account with a Bangladeshi SMS gateway (SSL Wireless, Alpha SMS, BulkSMSBD) or Twilio, and register a sender ID.
  2. Add SMS_API_KEY and SMS_SENDER_ID to server/src/config/env.js as optional values.
  3. In server/src/services/sms.service.js, make sendOtpSms call the gateway's HTTP API with fetch when the key is set, and keep the log-only mock when it isn't (development and tests).
  4. Log failures with logger.error but don't throw, so a slow gateway can't fail a sign-up. The resend limit in rateLimit.js already caps cost.
  5. Set the keys on Render, then remove the "Development mode: SMS is mocked" banner condition only if you want it gone in dev too.

Live payments

SSLCommerz runs in sandbox with the testbox store. The whole flow, including returning from the gateway, was verified end to end against the sandbox, so going live is configuration.

Before real usersNeeds a providerS

How to add

  1. Apply for a live SSLCommerz merchant account (trade license, bank details).
  2. On Render set SSLCOMMERZ_BASE_URL=https://securepay.sslcommerz.com, plus the live SSLCOMMERZ_STORE_ID and SSLCOMMERZ_STORE_PASSWORD.
  3. In the SSLCommerz merchant panel, set the IPN URL to https://<your-api>/api/v1/webhooks/payments/sslcommerz.
  4. Make one small real payment and refund it through Admin → Disputes to confirm both directions.

Private storage for driver documents

NID, license and police-clearance files sit in a public bucket under unguessable names. Anyone who has a link can open it.

Before real usersNew buildM

How to add

  1. In Supabase Storage, make the uploads bucket private.
  2. In server/src/routes/uploads.routes.js, store and return the object path (e.g. storage:uploads/ab12….png) instead of a public URL.
  3. Add a signedUrl(path) helper that calls POST /storage/v1/object/sign/uploads/<name> with the service key and a 10-minute expiry.
  4. Wherever documents are returned (documents.repository.js list functions, the admin driver/vehicle queues in admin.repository.js), map fileUrl through the helper before responding.
  5. Leave profile photos public, or give them their own public bucket.

Error monitoring

When something breaks for a rider you'd only find out if they tell you. Crashes and 500s should reach you with the stack trace.

Before real usersNeeds a providerS

How to add

  1. Create a free Sentry project for the API and one for the web app.
  2. Server: npm i @sentry/node, initialise it at the top of server/src/server.js with SENTRY_DSN, and call Sentry.captureException in errorHandler.js next to the existing logger.error.
  3. Client: npm i @sentry/react, initialise in client/src/main.tsx with VITE_SENTRY_DSN, and report from componentDidCatch in ErrorBoundary.tsx.
  4. Never send request bodies from auth or payment routes; Sentry's default scrubbing plus sendDefaultPii: false is enough.

Automated tests on every push, and nightly backups

351 server tests exist but only run by hand. Supabase's free plan has limited backups, so a bad migration or accidental delete is hard to undo.

Before real usersNew buildS

How to add

  1. Add .github/workflows/ci.yml with a postgres:16 service, then run npm ci, node server/scripts/db-init.js, npm --prefix server test, and npm --prefix client run lint && npm --prefix client run build.
  2. In GitHub → Settings → Branches, require that check before merging into main (Render and Vercel deploy from main).
  3. Add .github/workflows/backup.yml on a nightly schedule that runs pg_dump against the Supabase session-pooler URL (stored as a repository secret) and uploads the file to a private storage bucket.
  4. Keep the cron-job.org ping on /health every 10 minutes so Render stays awake and Supabase never pauses.

Ride experience

Matching, booking and in-trip features.

Re-offer a ride when a driver doesn't answer

Found in this check: if the only nearby driver lets an offer time out, the request is never offered again and the rider waits five minutes for "no driver found". The offer also stays "pending" on the server after the driver's countdown ends.

Before real usersDatabase readyM

How to add

  1. ride_offers.round already exists. Add an OFFER_TTL_SECONDS (e.g. 20) that matches the countdown in OfferSheet.tsx.
  2. Add server/src/jobs/redispatch.job.js (every 10 s, like expireRequests.job.js): mark pending offers older than the TTL timed_out, then for each request still searching, call dispatchService.fanOutOffers with round + 1, a wider radius, and excluding drivers already offered this request.
  3. Broadcast with dispatchService.broadcastNewOffers; the driver app already refreshes on offer:new.
  4. Cap rounds (e.g. 3) and let the existing expiry job end the request.

Schedule a ride for later

Airport runs and early classes. The server already accepts scheduledFor and skips instant dispatch; only the screen and a dispatcher job are missing.

Database readyM

How to add

  1. In BookRidePage.tsx, add "Now / Later" with a date-time input (limit to the next 7 days) and send scheduledFor in ridesApi.createRequest.
  2. Add a job that runs each minute and dispatches requests whose scheduled_for is within 10 minutes, reusing fanOutOffers.
  3. Show upcoming rides at the top of Trips with a Cancel button, and send a reminder notification 30 minutes before.

Surge pricing

Match supply and demand at rush hour and in rain. rides.service.js hard-codes NO_SURGE = 1.0 today.

Database readyM

How to add

  1. Use the existing surge_pricing table (zone, multiplier, reason, window).
  2. In buildQuote, look up the active row for the pickup zone (fn_zone_at) and time, cap it (e.g. 2.0×), and pass it to computeFare.
  3. Add a Surge tab to Admin → Pricing to create time-boxed multipliers per zone; audit each change like pricing rules.
  4. FareEstimateCard.tsx already shows a "× surge" badge when the multiplier is above 1.

Extra stops on a trip

Pick up a friend or stop at a shop on the way.

Database readyL

How to add

  1. Use the existing trip_stops table. Allow up to two stops in the booking sheet.
  2. Route through waypoints: OSRM accepts several coordinates; extend geo.service.route to take an array.
  3. Price on total distance and time, save the stops with the request, and show "Next stop" plus a "Stop reached" slider in DriverActiveTripPage.tsx.

Favourite drivers

Riders who liked a driver get matched with them first when they're nearby.

Database readyS

Share my trip with family

A link that shows the driver, car and live position without logging in. Especially valued by women riders at night.

New buildM

How to add

  1. Add POST /trips/:code/share that returns a signed, expiring token (JWT with the trip id, valid until the trip ends plus 1 hour).
  2. Add a public GET /share/:token returning driver first name, vehicle, status and latest position only.
  3. Add a public /share/:token page in the client using MapView, polling every 5 s.
  4. Add a "Share trip" button next to SOS; once SMS exists, send the link to emergency contacts automatically on SOS.

Round fares to whole taka

Quotes show paisa (৳307.46). Riders and drivers expect whole taka, especially for cash.

New buildS

How to add

  1. In server/src/utils/fareMath.js, round totalFare to the nearest taka (and the discount, so totals still add up).
  2. Update fareMath.test.js expectations. Commission math keeps two decimals, so driver earnings stay exact.

Money

Payments, payouts and promotions.

Promo code management for admins

Promo codes work at booking, but the only way to create one is SQL. Marketing needs a screen.

Database readyS

How to add

  1. Add GET/POST/PATCH /admin/promos over promo_codes (code, percent or fixed, cap, minimum fare, city, window, usage limit), with audit rows like pricing rules.
  2. Add a Promos page under Marketplace in AdminLayout.tsx, with redemption counts from promo_redemptions.
  3. Notify riders about new promos (category: 'promo').

Referrals

Cheapest growth channel for a ride app: "Give ৳50, get ৳50".

Database readyM

How to add

  1. Generate users.referral_code during sign-up in auth.service.register.
  2. Accept an optional referral code on the register form and record a referrals row (pending).
  3. When the new rider's first trip completes, credit both wallets with referral_bonus transactions (idempotency key per referral) and mark it rewarded.
  4. Add an "Invite friends" row to the Account page with the code and a copy button.

Automatic driver payouts

Withdrawals are approved by hand in Admin → Withdrawals, then paid outside the app.

Needs a providerL

How to add

  1. Get bKash or Nagad disbursement (B2C) API access.
  2. When an admin approves a withdrawal, call the disbursement API from withdrawals.service.js and move it through processing → paid or failed; these states already exist.
  3. Notify the driver at each step.

Monthly statements for drivers

Database readyM

  2. Add GET /driver/statements and a printable statement page linked from Earnings.

Run more than one API server

Only needed when one Render instance isn't enough. Rate limits and socket rooms currently live in one process's memory.

New buildM

How to add

  1. Add a Redis instance (e.g. Upstash free tier).
  2. Use rate-limit-redis in createRateLimiter and @socket.io/redis-adapter in sockets/index.js.
  3. Run the cron jobs in only one instance (an env flag), or move them to a scheduled job runner.

Maps and routing that scale

Routing and address search use free public servers that limit heavy traffic and can go down.

Needs a providerM

How to add

  1. Either self-host OSRM and Photon with Bangladesh-only data on a small VPS, or use a paid plan (Stadia Maps, MapTiler, Geoapify).
  2. Point OSRM_BASE_URL and PHOTON_BASE_URL at it on Render. The provider layer in server/src/services/providers/ already supports this.
  3. Cache geocoding results for common places in Postgres to cut calls.
