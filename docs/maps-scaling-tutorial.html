Cholo · operations guide

Maps and routing that scale

Every fare quote, address suggestion and route line in Cholo comes from outside map services. Today those are free public servers run by volunteers. This guide explains what that means for a real launch, what is already in place, and how to move to servers you control, step by step.

What Cholo uses today

Three kinds of map work, each from a different free service.

Routing · distance and time router.project-osrm.org Not for production

OSRM's demo server. Its policy allows about one request per second, with no uptime promise. Every quote, booking and trip completion calls it.

Address search and reverse photon.komoot.io Fair use only

Komoot's public Photon. Heavy use gets throttled. It powers the pickup and dropoff suggestions and “current location” names.

Map tiles · the picture tiles.openfreemap.org Fine for launch

OpenFreeMap serves tiles free with no key. The browser loads them directly, so they never touch your API.

You will know you have outgrown the public servers when Render's logs show GEO_PROVIDER_UNAVAILABLE, riders see “The mapping service is temporarily unavailable”, suggestions arrive slowly, or quotes fail at busy times. A few hundred riders a day is roughly where that starts.

Changed in this update: search now uses Photon in production

The Render blueprint had address search on the public Nominatim server. Nominatim's usage policy forbids search-as-you-type, which is exactly what the booking suggestions do, so the blueprint now sets GEO_PROVIDER=photon. If Render doesn't sync blueprint changes automatically, set it yourself: Render → cholo-api → Environment → GEO_PROVIDER = photon.

Already done in the code

You don't need to build these; they shipped with this update.

  • One switch per service. OSRM_BASE_URL and PHOTON_BASE_URL decide which servers the API calls. Pointing them at your own servers needs no code change.
  • A short memory cache. server/src/services/geo.service.js keeps route, search and reverse results for 10 minutes (up to 1,000 entries). Quoting four categories for the same trip, or two riders searching “Dhanmondi 27”, now costs one outside call instead of several.
  • A private-server key. Set GEO_UPSTREAM_TOKEN and the API sends Authorization: Bearer <token> with every map request, so your own servers can refuse anyone else. Only set it when the URLs point at your servers, or the token would be sent to the public ones.
  • Bangladesh-only results. Search is limited to Bangladesh's bounding box, and routes that cross the border are rejected or rerouted, whichever server you use.

Self-host routing and search

About an hour the first time. You need a credit card for the server and, ideally, a domain name.

Rent a server

Create an Ubuntu 24.04 server with 4 vCPU, 8 GB RAM and 40 GB disk. Building the Bangladesh route data needs several GB of memory; running it afterwards needs much less. Choose a location close to Bangladesh or to Render's region (Singapore if your Render service is there).

Note its public IP address, then log in with ssh root@YOUR_SERVER_IP.

Install Docker, Java and Caddy, and open the firewall

# Docker (runs OSRM), Java 21 (runs Photon), Caddy (HTTPS in front of both)
apt update && apt install -y docker.io openjdk-21-jre-headless debian-keyring debian-archive-keyring apt-transport-https curl ufw pbzip2
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' > /etc/apt/sources.list.d/caddy-stable.list
apt update && apt install -y caddy

# Only SSH and HTTPS from outside; OSRM and Photon stay on localhost
ufw allow 22 && ufw allow 80 && ufw allow 443 && ufw --force enable

Download Bangladesh's map data

Geofabrik publishes a daily OpenStreetMap extract for Bangladesh.

mkdir -p /srv/osrm && cd /srv/osrm
curl -LO https://download.geofabrik.de/asia/bangladesh-latest.osm.pbf

Build and start the routing server (OSRM)

These three commands turn the map into a routing graph with the car profile. It takes 5–20 minutes. The car profile also gives sensible distances and times for bikes and CNGs.

cd /srv/osrm
docker run --rm -t -v /srv/osrm:/data ghcr.io/project-osrm/osrm-backend osrm-extract -p /opt/car.lua /data/bangladesh-latest.osm.pbf
docker run --rm -t -v /srv/osrm:/data ghcr.io/project-osrm/osrm-backend osrm-partition /data/bangladesh-latest.osrm
docker run --rm -t -v /srv/osrm:/data ghcr.io/project-osrm/osrm-backend osrm-customize /data/bangladesh-latest.osrm

# Run it on localhost:5000, restarting automatically after reboots
docker run -d --name osrm --restart unless-stopped -p 127.0.0.1:5000:5000 -v /srv/osrm:/data \
  ghcr.io/project-osrm/osrm-backend osrm-routed --algorithm mld /data/bangladesh-latest.osrm

# Test: Gulshan 2 → Dhanmondi 27. Expect "code":"Ok" and a distance around 9,000 m
curl -s "http://127.0.0.1:5000/route/v1/driving/90.4078,23.7925;90.3742,23.7461?overview=false" | head -c 300
If osrm-extract stops with “Killed”

The server ran out of memory. Add swap (fallocate -l 8G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile) and run the extract again, or use a larger server just for the build.

Set up address search (Photon)

Photon publishes ready-made search indexes per country. Open the Bangladesh extracts folder, copy the link of the newest file, and download the matching Photon release from github.com/komoot/photon/releases. The index and the jar must come from the same Photon version; the Photon README lists which goes with which.

mkdir -p /srv/photon && cd /srv/photon
# Paste the two links you copied
curl -L -o photon.jar "PASTE_PHOTON_JAR_LINK"
curl -L "PASTE_BD_EXTRACT_LINK" | pbzip2 -d | tar x    # creates /srv/photon/photon_data

# Run as a service on localhost:2322
cat > /etc/systemd/system/photon.service <<'EOF'
[Unit]
Description=Photon geocoder (Bangladesh)
After=network.target

[Service]
WorkingDirectory=/srv/photon
ExecStart=/usr/bin/java -Xmx2g -jar /srv/photon/photon.jar -data-dir /srv/photon -listen-ip 127.0.0.1 -listen-port 2322
Restart=always

[Install]
WantedBy=multi-user.target
EOF
systemctl daemon-reload && systemctl enable --now photon

# Test (give it half a minute to start). Expect a list of Dhanmondi places
curl -s "http://127.0.0.1:2322/api/?q=Dhanmondi%2027&limit=3" | head -c 400

Put HTTPS and a key in front (Caddy)

Point two DNS names at your server's IP with A records, for example route.yourdomain.com and geo.yourdomain.com. No domain yet? route.203-0-113-5.sslip.io (your IP with dashes) resolves to your server automatically and works for HTTPS too.

Make a long random key; the API will send it and Caddy will refuse requests without it.

# 1. Generate the key and keep it for step 7
openssl rand -hex 32

# 2. Give it to Caddy
mkdir -p /etc/systemd/system/caddy.service.d
printf '[Service]\nEnvironment=GEO_TOKEN=PASTE_THE_KEY\n' > /etc/systemd/system/caddy.service.d/token.conf

# 3. Replace the domains with yours
cat > /etc/caddy/Caddyfile <<'EOF'
route.yourdomain.com {
	@denied not header Authorization "Bearer {$GEO_TOKEN}"
	respond @denied 401
	reverse_proxy 127.0.0.1:5000
}

geo.yourdomain.com {
	@denied not header Authorization "Bearer {$GEO_TOKEN}"
	respond @denied 401
	reverse_proxy 127.0.0.1:2322
}
EOF
systemctl daemon-reload && systemctl restart caddy

# 4. From your laptop: without the key → 401, with it → "code":"Ok"
curl -s -o /dev/null -w "%{http_code}\n" "https://route.yourdomain.com/route/v1/driving/90.4078,23.7925;90.3742,23.7461"
curl -s -H "Authorization: Bearer PASTE_THE_KEY" "https://route.yourdomain.com/route/v1/driving/90.4078,23.7925;90.3742,23.7461?overview=false" | head -c 200

Caddy gets the HTTPS certificates by itself on first request. If it can't, check that both DNS names point at this IP and that ports 80 and 443 are open.

Connect Cholo to your servers

Render → cholo-api → Environment. Save, and Render redeploys in about a minute.

VariableValue
GEO_PROVIDERphoton
OSRM_BASE_URLhttps://route.yourdomain.com (no trailing slash)
PHOTON_BASE_URLhttps://geo.yourdomain.com
GEO_UPSTREAM_TOKENthe key from the Caddy step

Then check it end to end:

  1. Open Cholo, type an address in Pickup, and confirm suggestions appear quickly.
  2. Pick a dropoff and confirm fares and the green route line appear.
  3. In Render → Logs, confirm there are no GEO_PROVIDER_UNAVAILABLE errors.
  4. On the map server, journalctl -u caddy -n 20 shows the requests arriving from Render.
Nothing else changes

The web app never calls these servers directly. It asks the Cholo API, which applies the Bangladesh checks and the cache, so riders need no update.

Keep the map data fresh

New roads and places reach OpenStreetMap every day. Rebuilding once a month is plenty.

This script builds new route data in a separate folder and only swaps it in when the build succeeds, so routing keeps working during the rebuild.

cat > /usr/local/bin/refresh-osrm <<'EOF'
#!/bin/sh
set -e
NEW=/srv/osrm-next
rm -rf "$NEW" && mkdir -p "$NEW" && cd "$NEW"
curl -sLO https://download.geofabrik.de/asia/bangladesh-latest.osm.pbf
IMG=ghcr.io/project-osrm/osrm-backend
docker run --rm -v "$NEW":/data $IMG osrm-extract -p /opt/car.lua /data/bangladesh-latest.osm.pbf
docker run --rm -v "$NEW":/data $IMG osrm-partition /data/bangladesh-latest.osrm
docker run --rm -v "$NEW":/data $IMG osrm-customize /data/bangladesh-latest.osrm
docker stop osrm && docker rm osrm
rm -rf /srv/osrm-old && mv /srv/osrm /srv/osrm-old && mv "$NEW" /srv/osrm
docker run -d --name osrm --restart unless-stopped -p 127.0.0.1:5000:5000 -v /srv/osrm:/data $IMG osrm-routed --algorithm mld /data/bangladesh-latest.osrm
EOF
chmod +x /usr/local/bin/refresh-osrm

# 03:00 on the 1st of every month (server time)
echo "0 3 1 * * root /usr/local/bin/refresh-osrm >> /var/log/refresh-osrm.log 2>&1" > /etc/cron.d/refresh-osrm

Routing pauses for a few seconds during the swap. For Photon, repeat the download from the address-search step every few months, then run systemctl restart photon.

Alternative: a paid map API

No server to run, but you pay per request above the free tier and need one new file.

Paid APIs don't speak OSRM's and Photon's formats, so add a provider next to the existing ones. Every provider exports the same four functions, and geo.service.js picks one by GEO_PROVIDER.

What each function returns

  • route(from, to, { via }) → { distanceKm, durationMin, path: [{ lat, lng }], alternatives: [] }
  • search(text) → up to 5 { lat, lng, address, countryCode }
  • geocode(text) → one of those
  • reverseGeocode(lat, lng) → { address, countryCode }

Where to add it

  1. Create server/src/services/providers/geoapify.provider.js.
  2. Add it to the providers map in geo.service.js.
  3. Add 'geoapify' to the GEO_PROVIDER list and a GEOAPIFY_API_KEY in server/src/config/env.js.
  4. Copy tests/unit/photon.provider.test.js and adapt it.

A starting point using Geoapify's routing and autocomplete endpoints (check their documentation for the current response fields):

import { env } from '../../config/env.js';
import { AppError } from '../../utils/AppError.js';

const BASE = 'https://api.geoapify.com/v1';
const key = () => `apiKey=${env.GEOAPIFY_API_KEY}`;

async function get(url) {
  const response = await fetch(url).catch(() => null);
  if (!response?.ok) throw new AppError(503, 'GEO_PROVIDER_UNAVAILABLE');
  return response.json();
}

export async function route(from, to, { via = [] } = {}) {
  const waypoints = [from, ...via, to].map((p) => `${p.lat},${p.lng}`).join('|');
  const data = await get(`${BASE}/routing?waypoints=${waypoints}&mode=drive&${key()}`);
  const feature = data.features?.[0];
  if (!feature) throw new AppError(422, 'ROUTE_NOT_FOUND');
  const lines = feature.geometry.type === 'MultiLineString' ? feature.geometry.coordinates.flat() : feature.geometry.coordinates;
  return {
    distanceKm: Math.round(feature.properties.distance / 10) / 100,
    durationMin: Math.max(1, Math.round(feature.properties.time / 60)),
    path: lines.map(([lng, lat]) => ({ lat, lng })),
    alternatives: [],
  };
}

const toPlace = (p) => ({ lat: p.lat, lng: p.lon, address: p.formatted, countryCode: p.country_code });

export async function search(text) {
  const data = await get(`${BASE}/geocode/autocomplete?text=${encodeURIComponent(text)}&filter=countrycode:bd&limit=5&format=json&${key()}`);
  return (data.results ?? []).map(toPlace);
}

export async function geocode(text) {
  const [first] = await search(text);
  if (!first) throw new AppError(422, 'ADDRESS_NOT_FOUND');
  return first;
}

export async function reverseGeocode(lat, lng) {
  const data = await get(`${BASE}/geocode/reverse?lat=${lat}&lon=${lng}&format=json&${key()}`);
  const place = data.results?.[0];
  if (!place) throw new AppError(422, 'ADDRESS_NOT_FOUND');
  return { address: place.formatted, countryCode: place.country_code };
}

With the cache in place, a quote costs one routing request per trip rather than one per category, and repeated searches are free for 10 minutes. That keeps a small app within most free tiers for a while.

The map picture itself (tiles)

No action needed at launch.

The map background comes from OpenFreeMap, set as VECTOR_STYLE_URL in client/src/components/map/MapView.tsx. It is free, needs no key and serves tiles from a CDN, so riders' phones load it directly without touching your API or your map server.

If you ever want to stop depending on it, the simplest route is a single Bangladesh file in the Protomaps PMTiles format hosted on any static file host, with MapView's style pointed at it. A paid tile plan (MapTiler, Stadia Maps) also only needs that one style URL changed.

Troubleshooting and rollback

Rolling back takes one minute

In Render, set OSRM_BASE_URL back to https://router.project-osrm.org, PHOTON_BASE_URL to https://photon.komoot.io, and delete GEO_UPSTREAM_TOKEN. Cholo goes straight back to the public servers.
